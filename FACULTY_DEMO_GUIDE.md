# Faculty Demonstration Guide

## Agent-Based University Scheduling Simulator

**Audience:** Faculty evaluator / examiner  
**Duration:** 15–20 minutes  
**Pre-requisite:** `streamlit run app.py` is running at http://localhost:8501

---

## Part 1 — System Overview (2 min)

**Point to the Dashboard tab.**

> "This system models university timetabling as a Distributed Constraint Satisfaction Problem. 
> Three types of autonomous agents — Teacher, Room, and Student — negotiate time slots 
> and rooms through formal messages. No central authority decides the timetable; 
> every decision is made by the agents themselves."

Key metrics visible on the Dashboard:
- Number of each agent type
- Scheduled vs. unscheduled sessions
- Total negotiation rounds
- Proposals accepted and rejected
- NOGOOD messages generated

## Key AI Concepts Demonstrated

| Concept | Where to See It |
|---------|----------------|
| Distributed CSP | Each agent enforces its own constraints |
| Contract Net Protocol | CFP → BID → AWARD pattern in Timeline |
| Asynchronous Backtracking | NOGOOD → RELEASE → BACKTRACK in Timeline |
| Agent view | T1's priority causes lower-priority teachers to avoid its committed slots |
| Nogood learning | S7's nogood count; repeated slots avoided without re-checking |
| Soft-constraint utility | Optimization Analysis tab — utility scores per session |
| Independent validation | Constraint Inspector runs H1–H6 after agents finish |

## Talking Points for Questions

**Q: Is this truly distributed?**  
A: The agents have fully independent state and communicate only through explicit messages. 
The execution is sequential for reproducibility, but each agent's decision is self-contained. 
The architecture is directly portable to a genuinely distributed network.

**Q: How does backtracking work?**  
A: TeacherAgents are ordered by priority. When a lower-priority teacher hits a conflict 
that stems from a higher-priority teacher's committed slot, it records a nogood and skips 
that slot in all future negotiations for that session.

**Q: What prevents false success?**  
A: The independent ConstraintValidator in `constraints.py` re-checks H1–H6 from scratch. 
It has no knowledge of which agent made which decision — it only sees the final timetable.

**Q: What is the room cost function?**  
A: `cost = capacity - enrollment + building_bonus` where `building_bonus = 5` for off-campus. 
Lower cost is preferred — the best-fit room wins.
